# MoneyManager 产品说明书

## 一、项目概述

MoneyManager 是一款简洁的个人记账理财应用，基于原生 JavaScript、HTML 和 CSS 开发，使用 localStorage 实现数据持久化存储。应用支持支出/退款/垫付三种交易类型，提供月份导航、日历选择、批量管理、月度复盘、快捷记账、消费热力图和动态预算等功能。

---

## 二、功能模块

### 2.1 记账功能

#### 2.1.1 基础记账

用户可输入金额、选择分类、添加备注后提交记录。

**交互流程**：
1. 输入金额（必填，必须大于0）
2. 选择分类（默认显示第一个分类，可切换）
3. 选择日期（默认今天，可通过日历选择）
4. 添加备注（可选，最大20字符）
5. 可选"垫付"标记
6. 点击"记一笔"提交

**特殊规则**：
- 选择"退款"分类时，自动将类型设为退款
- 累计支出达到上限（1亿）时禁止新增
- 每次提交成功后，自动记录该分类的上次使用金额（用于快捷记账）

#### 2.1.2 快捷记账

针对固定金额的重复支出场景，一键完成记账。

**入口**：记账表单底部的"⚡ 快速记账"按钮

**交互流程**：
1. 点击按钮 → 底部弹出快速记账面板
2. 面板显示所有分类，每个分类下方显示**上次使用的金额**
3. 点击任意分类 → 直接使用该分类的上次金额快速提交
4. 显示成功提示，面板自动关闭

**数据存储**：`mm_lastAmounts` 存储各分类上次金额

**边界处理**：
- 如果某分类从未使用过，不显示金额
- 金额为0时点击无效

### 2.6 预算模块

#### 2.6.1 月度预算基础

**数据模型**：

```javascript
{
  budgets: {
    '2026-05': {
      amount: 3000,
      excludeIds: ['tx123', 'tx456'],
      target: '攒钱买iPhone',
      workMode: 'double'
    }
  }
}
```

**功能点**：
- 用户可设置任意月份的预算金额
- 预算数据存储在 localStorage，支持跨月份查看
- 默认显示当前月份，可切换查看历史/未来月份

#### 2.6.2 动态日预算计算

**核心原则**：类似通关游戏，可查看当月每一天的预算及完成情况。

**日预算计算公式**：

```
对于第 N 天：
日预算_N = (月预算 - Σ实际支出_从Day1到Day(N-1)) / (当月总天数 - N + 1)
```

**示例**（5月共31天，月预算3000）：

| 日期 | 前N-1天实际支出 | 剩余天数 | 日预算 |
|------|----------------|---------|--------|
| 5月1日 | ¥0 | 31 | ¥96.77 |
| 5月2日 | ¥100 | 30 | ¥96.67 |
| 5月3日 | ¥300 | 29 | ¥93.10 |
| 5月15日 | ¥1500 | 17 | ¥88.24 |
| 5月31日 | ¥2800 | 1 | ¥200 |

**计算策略**：采用"实时回推"方案（不存储快照）

选择实时回推的原因：
1. **MVP阶段足够满足需求**：补录本就是"补充历史"，自然会产生回推效果
2. **补录联动感知**：用户补录时能直观看到历史预算被重新评估，形成"蝴蝶效应"的趣味感
3. **实现简单**：无需维护快照存储逻辑

**特殊场景处理**：

| 场景 | 处理策略 |
|------|---------|
| 预算提前用完 | 未来日预算显示为 ¥0，状态统一标记为 "OVER" |
| 未设置预算 | 不显示日预算列，仅显示实际支出和状态 |
| 跨月补录 | 仅影响补录所在月份，不跨月联动 |

#### 2.6.3 每日状态定义

```javascript
function getDayStatus(budget, actual) {
  if (actual === 0) return 'EMPTY';
  const ratio = actual / budget;
  if (ratio <= 0.8) return 'GREAT';
  if (ratio <= 1.1) return 'GOOD';
  if (ratio <= 1.5) return 'WARN';
  return 'OVER';
}
```

**状态标签对照**：

| 状态 | 标签 | 触发条件 | 颜色 |
|------|------|---------|------|
| GREAT | 🎉 GoodJob! | 实际 ≤ 预算×80% | 绿色 |
| GOOD | ✓ Good | 实际 ≤ 预算×110% | 浅绿 |
| WARN | ⚠️ ComeOn | 实际 ≤ 预算×150% | 橙色 |
| OVER | 💸 Over | 实际 > 预算×150% | 红色 |
| EMPTY | — | 无消费 | 灰色 |
| FUTURE | ... | 未来日期 | 虚线 |

## 三、数据结构

### 交易记录 (Transaction)

```javascript
{
  id: string,          // 唯一标识
  subType: string,     // 'expense' | 'refund' | 'advance'
  amount: number,      // 金额
  category: string,    // 分类名称
  note: string,        // 备注（可选）
  date: string,        // 日期 'YYYY-MM-DD'
  createdAt: number,   // 创建时间戳
  excludeFromBudget: boolean  // 是否不计入预算
}
```

### 预算记录 (Budget)

```javascript
{
  amount: number,       // 预算金额
  excludeIds: string[], // 不计入预算的交易ID列表
  target: string,       // 预算目标描述
  workMode: string      // 'single' | 'double'
}
```
