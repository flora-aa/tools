# 数据继承功能说明书

## 一、功能概述

数据继承功能解决用户在多设备间迁移记账数据的需求。当用户更换设备时，可将旧设备的全部数据通过 **GitHub Gist** 安全地转移到新设备。

### 核心原则

- **Rebase 模式**：继承者的本地数据将被完全清空，替换为被继承者的数据（不合并、不解冲突）
- **Gist ID 直传**：被继承者上传数据到 Gist，将 Gist ID 告知继承者，继承者下载即可
- **去中心化存储**：数据不经过第三方服务器，通过 GitHub Gist API 直传

---

## 二、角色定义

| 角色 | 说明 | 操作 |
|------|------|------|
| **被继承者（Donor）** | 旧设备，数据来源方 | 输入 Token → 上传数据到 Gist → 复制 Gist ID |
| **继承者（Inheritor）** | 新设备，数据接收方 | 输入 Token + Gist ID → 下载数据 → 刷新 |

> **同一设备可同时担任两个角色**：例如用户先作为继承者从旧设备获取数据，然后作为被继承者将数据传给另一台设备。

```

│                              │

```

**详细步骤**：

1. 用户切换到"导出数据"Tab
2. 系统自动展示数据概览（交易笔数、时间跨度、预算配置数）
3. 用户输入 GitHub Personal Access Token
4. 点击"导出并上传到 Gist"按钮
5. 系统将所有数据序列化为 JSON，通过 Gist API 创建 Gist
6. 上传成功后，以大字号显示 Gist ID
7. 用户点击"复制 Gist ID"，通过微信/QQ/短信等方式发给继承者
8. 点击"完成"退出

```
┌──────────────┐
│  切换到"导入数据" │
└──────┬───────┘
       │
       ▼

│                              │
│  GitHub Token                │
│  ┌──────────────────────┐    │
│  │ ghp_xxxxxxxxxxxxxx   │    │
│  └──────────────────────┘    │
│                              │
│  Gist ID                     │
│  ┌──────────────────────┐    │
│  │ a1b2c3d4e5f6         │    │
│  └──────────────────────┘    │
│                              │
│  [  导入并继承数据  ]        │
└──────────┬───────────────────┘
           │ 点击导入
           ▼
    ┌──────────────────┐
    │  二次确认弹窗      │
    │  ──────────────   │
    │  确认数据继承？    │
    │  此操作不可撤销！   │
    │  [取消] [确认继承] │
    └────────┬─────────┘
             │ 确认
             ▼
┌──────────────────────────────┐
│  ⏳ 正在下载数据...           │
│  下载完成 → 自动刷新页面      │
└──────────────────────────────┘
```

**详细步骤**：

1. 用户切换到"导入数据"Tab
2. 阅读风险提示（`⚠️ 此操作将清空所有本地数据`）
3. 输入 GitHub Personal Access Token（与被继承者**可以不同账号**，只需 Token 有读取 Gist 的权限）
4. 输入被继承者告知的 Gist ID
5. 点击"导入并继承数据"按钮
6. 弹出二次确认弹窗
7. 用户点击"确认继承"
8. 系统：
   1. 清空所有本地数据（`localStorage.clear()`）
   2. 从 Gist 获取数据
   3. 写入 `localStorage`
   4. 自动刷新页面
9. 刷新后数据完全同步为被继承者的数据

> **为什么继承者也需要 Token？** 即使只是读取 Gist，GitHub API 也需要认证。继承者使用自己的 Token 即可，无需与被继承者同一账号——只要 Gist 是公开的，任何 Token 都能读取。

## 四、令牌管理（GitHub Token）

### Token 要求

| 要求 | 说明 |
|------|------|
| 类型 | GitHub Personal Access Token (classic) |
| 最小权限 | `gist`（仅 Gist 读写） |
| 有效期 | 无过期限制（用户自行管理） |

### 安全性

- Token **仅存储在内存中**，不会写入 `localStorage`
- 传输过程全程 HTTPS（GitHub API）
- 导入/导出流程结束后 Token 自动清除

### 获取方式

用户在 GitHub → Settings → Developer settings → Personal access tokens → Generate new token (classic) → 勾选 `gist` 权限 → 生成并复制 Token。

## 五、Gist 数据格式

### Gist 命名规则

Gist 描述（Description）统一为：`MoneyManager Data Export`

Gist 内文件名固定为：`mm-data.json`

### Gist 文件内容

```json
{
  "version": 1,
  "exportedAt": "2026-05-10T15:30:00.000Z",
  "data": {
    "mm_transactions": [
      {
        "id": "tx_abc123",
        "subType": "expense",
        "amount": 3500,
        "category": "餐饮",
        "note": "午餐",
        "date": "2026-05-10",
        "createdAt": 1715328000000,
        "excludeFromBudget": false
      }
    ],
    "mm_memos": {
      "2026_5": "本月预算控制得不错",
      "2026_4": ""
    },
    "mm_budgets": {
      "2026-05": {
        "amount": 5000,
        "excludeIds": ["tx_def456"],
        "target": "攒钱买手机",
        "workMode": "double"
      }
    },
    "mm_lastAmounts": {
      "餐饮": 35,
      "交通": 15,
      "购物": 200
    }
  }
}
```

### 继承的完整数据范围

| localStorage Key | 说明 | 继承 |
|-----------------|------|------|
| `mm_transactions` | 交易记录 | ✅ |
| `mm_budgets` | 预算配置 | ✅ |
| `mm_lastAmounts` | 分类上次金额 | ✅ |
| `mm_memo_*` | 月度小结 | ✅（导出时合并为嵌套对象，导入时逐个还原） |
| `mm_theme` | 主题设置 | ❌（沿用新设备主题） |

## 六、继承规则（Rebase 模式）

### 数据清空策略

执行导入时，继承者设备执行：

```javascript
localStorage.clear();
// 写入 incoming.data 中的所有 Key
// 跳过分组的数据（mm_memos 展开写入 mm_memo_*）
location.reload();
```

### 不继承的内容

| 项目 | 原因 |
|------|------|
| 主题配色（`mm_theme`） | 新设备可能有不同屏幕尺寸/个人偏好 |
| 页面布局状态 | 无关数据 |
| 浏览器缓存 | 非业务数据 |

## 七、安全边界与容错处理

| 场景 | 处理方式 |
|------|---------|
| Token 无效 | 提示"Token 无效，请检查 GitHub Token 及 gist 权限" |
| Gist ID 不存在 | 提示"未找到该 Gist，请确认 Gist ID 是否正确" |
| 网络超时 | 显示"网络连接超时，请检查网络后重试"，保留已输入 Token 和 Gist ID |
| 下载中断 | 已清空的数据无法恢复 → **下载开始前二次确认弹窗** |
| 数据格式不兼容 | 提示"数据版本不兼容，请确认双方应用版本一致" |
| Token 权限不足 | 提示"Token 权限不足，请确保已勾选 gist 权限" |

### 二次确认机制

导入操作不可逆，继承者点击"导入"后将弹出确认弹窗：

```
⚠️ 确认数据继承

此操作将：
• 清空本设备上的所有记账数据
• 替换为旧设备导出的数据

此操作不可撤销！

[ 取消 ]  [ 确认继承 ]
```

## 九、容错处理清单

| 错误场景 | 用户提示 | 恢复方式 |
|---------|---------|---------|
| Token 格式错误 | "Token 格式不正确，应以 ghp_ 开头" | 清空输入框，重新输入 |
| Gist ID 格式错误 | "Gist ID 格式不正确" | 清空输入框，重新输入 |
| 403 权限不足 | "Token 权限不足，请确保已勾选 gist 权限" | 保留输入，修改 Token 后重试 |
| 404 Gist 不存在 | "未找到该 Gist，请确认 Gist ID 是否正确" | 保留输入，修改 Gist ID 后重试 |
| 网络超时 | "网络连接超时，请检查网络后重试" | 保留输入，点击重试 |
| 数据格式异常 | "数据格式异常，请确认来源应用版本一致" | 清空已下载数据 |
| 导出数据为空 | "没有可导出的数据" | 阻止导出操作 |
